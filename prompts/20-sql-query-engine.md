You are implementing an in-memory SQL/relational query execution engine and cost-based query processor (`executeRelationalQuery`).

Signature: `executeRelationalQuery(database, queryPlan)`

### 1. Database Model (`database` object)
- `tables`: map of table objects by name:
  `{ [tableName]: { columns: string[], rows: Record<string, any>[] } }`
- `indexes`: map of secondary/B-Tree index objects:
  `{ [indexName]: { table: string, column: string, entries: Array<{ key: any, rowIndices: number[] }> } }`

### 2. Relational Query Plan AST (`queryPlan` object)
The query plan is a tree of relational algebra operator nodes. Each node has an `op` type and its specific parameters:

1. **`SCAN`**: `{ op: "SCAN", table: string, filter?: Predicate, columns?: string[] }`
   - Scans the underlying table rows.
   - Evaluates the optional boolean `filter` predicate on each row.
   - Attributes can be referenced as both unqualified (`col`) and fully qualified (`table.col`).

2. **`INDEX_SCAN`**: `{ op: "INDEX_SCAN", table: string, index: string, eq?: any, range?: { min?: any, max?: any }, filter?: Predicate, columns?: string[] }`
   - Performs an index-accelerated lookup on the specified `index`.
   - If `eq` is provided, retrieves rows matching the exact index key.
   - If `range` is provided, retrieves rows where index key satisfies `min <= key <= max`.
   - Applies any post-scan `filter` predicates.

3. **`JOIN`**: `{ op: "JOIN", type: "INNER" | "LEFT" | "RIGHT" | "FULL", left: PlanNode, right: PlanNode, on: [string, string], columns?: string[] }`
   - Equi-join on `leftRow[on[0]] === rightRow[on[1]]`.
   - `"INNER"`: only emitting rows where keys match on both sides.
   - `"LEFT"`: all left rows preserved, padding with `null` for missing right columns.
   - `"RIGHT"`: all right rows preserved, padding with `null` for missing left columns.
   - `"FULL"`: outer join preserving all rows from both relations with null padding.

4. **`FILTER`**: `{ op: "FILTER", source: PlanNode, condition: Predicate }`
   - Filters the upstream rows using the specified `condition`.

5. **`AGGREGATE`**: `{ op: "AGGREGATE", source: PlanNode, groupBy: string[], aggs: Array<{ fn: "COUNT" | "SUM" | "AVG" | "MIN" | "MAX", col: string, alias?: string }>, having?: Predicate, columns?: string[] }`
   - Groups upstream rows by the specified `groupBy` column keys. If `groupBy` is empty, computes global aggregations over all rows (returning a single summary row).
   - Computes aggregate functions:
     - `COUNT`: `col === "*"` counts all rows in group; specific column counts non-null values.
     - `SUM`: numeric sum of non-null values in the group (or 0 if empty).
     - `AVG`: arithmetic mean rounded to 2 decimal places (`Math.round(mean * 100) / 100`), or `null` if empty.
     - `MIN`: minimum non-null value (or `null`).
     - `MAX`: maximum non-null value (or `null`).
   - Evaluates optional `having` predicate against the aggregated row.

6. **`SORT`**: `{ op: "SORT", source: PlanNode, orderBy: Array<{ col: string, desc?: boolean }>, columns?: string[] }`
   - Deterministic multi-column sort. Nulls are sorted last by default.

7. **`LIMIT`**: `{ op: "LIMIT", source: PlanNode, limit?: number, offset?: number, columns?: string[] }`
   - Slices the sorted/aggregated rows with offset and limit pagination.

### 3. Predicate Evaluation
A predicate object can be:
- Compound: `{ and: Predicate[] }`, `{ or: Predicate[] }`, `{ not: Predicate }`.
- Column comparison: `{ col: string, op: "=" | "!=" | ">" | ">=" | "<" | "<=" | "IN" | "IS_NULL" | "IS_NOT_NULL", val?: any }`.
